# 365Canopy Windows desktop preview

Run `365Canopy.exe` from the complete portable directory, or use the per-user `365Canopy-0.1.0-alpha.8-Setup.exe` installer. It includes .NET and PowerShell 7.6.6. On first use choose Set up audit dependency, review the linked component terms, then download PnP.PowerShell 3.4.1 directly from PowerShell Gallery. The archive SHA-256 must match the reviewed release before extraction or import. Setup uses no tenant credentials. The module is reused from `%LOCALAPPDATA%/365Canopy/modules/PnP.PowerShell/3.4.1`; uninstall preserves it. If setup is cancelled or fails, retry it. An incomplete folder must be removed manually before retry; no existing installation is overwritten. Installer and application are unsigned development previews; publisher signing and clean-machine installation remain release validation gates.

Connection fields start blank. The application does not use browsing history or automatically load a saved connection. Saved sites let you explicitly store and load a friendly name, site URL, library, tenant/client IDs and audit options. They are saved outside the repository at `%LOCALAPPDATA%/365Canopy/sites.protected`, protected with Windows DPAPI for the current user. No credentials, access tokens or audit results are stored in profiles. Forget site removes saved metadata; corrupt or unreadable files are preserved rather than overwritten. Uninstall leaves per-user profiles in place. Enter the SharePoint site root, expected tenant GUID, registered public client ID and library. Include file-level permissions review is optional and unchecked by default. Check it to review every file throughout the library; this includes recursive folders. Leave it unchecked to review library/folder permissions, then choose Run administrator audit. Live discovery and permission-review counts appear while collection runs. Microsoft handles sign-in/MFA. The runtime does not create registrations, grant consent, elevate site access or change permissions. The configured delegated Full Control permission is write-capable; the fixed collector makes read operations. Cancelling terminates the isolated process; browser/OS sign-in state can remain.

The Lantern-style navigation rail has Audit, Results, Coverage and Report pages. Connection and scope controls use aligned cards; exports live on the Report page. The Audit page holds connection settings. A tree at the right of the Audit scope card sways during collection; Windows animation preferences are respected. Successful collection and JSON import automatically show Results, which contains no connection fields. Browse resources on the left, observed grants in the middle and classic SharePoint / Entra membership paths on the right. Owners claims expand through Graph owners, not members. Nested group traversal is bounded and cycle-safe. Missing names display object IDs and an explicit identity-detail gap. Graph delegated User.ReadBasic.All enables basic user names and usernames; missing profiles are retried by object ID with bounded, cached GET requests. Failure retains IDs and records identity gaps. Hidden membership and Graph v1.0 service-principal omissions remain limitations.

Coverage is available through its own navigation entry. File role assignments and inherited permissions are collected throughout the selected document library. Sharing-link URLs, expiry and recipient details are not collected. Sharing principals returned by role assignments are preserved without interpreting their link reach. File contents and versions are not opened or downloaded. Discovery stops after 40,000 returned items; a stopped or failed discovery is reported as partial, with prior evidence retained. Library ItemCount is compared against discovered folders and files; agreement is a cross-check, not proof of untrimmed visibility or an atomic snapshot. Unreadable items remain in Results with unknown permissions; descendants of an unresolved ancestor do not fall back to library permissions. A missing grant or person is not proof of no access. This preview is not a complete effective-access evaluator.

Audit evidence travels through an isolated child-process pipe and remains in application memory until explicit export. HTML is the human-readable offline report with a collapsible site/library/folder/file tree and group-to-person membership branches: summary, file counts, resource navigation, unique/inherited permissions, grants, membership paths, usernames/object IDs and coverage. Inherited files link to their ancestor permission set, avoiding repeated membership tables for large libraries. It follows system light/dark preferences, supports browser printing and loads no external resources or scripts. CSV uses resource, grant, membership and coverage rows, repeats ancestor grants for inherited resources, includes access paths, and neutralizes spreadsheet formula cells. JSON retains the original snapshot and can be reopened. Exports are bounded to 250,000 expanded rows; use JSON if that limit is reached. Exports may contain private tenant identities. The app does not upload evidence or save sign-in credentials; Microsoft runtime/browser state is outside that boundary. Theme follows System or can be changed to Light/Dark. The resource palette and high-contrast handling follow the Lantern pattern, with Canopy green as the accent.

Build using `scripts/Build-Desktop.ps1`. The build uses dotnet on PATH, an explicitly supplied official signed PowerShell runtime and installed Inno Setup 6. Override tool paths for another build machine. Runtime licenses and Canopy MIT terms are included in the package. PnP, MSAL NativeInterop and CSOM are excluded and the build rejects their presence. Ignored tenant snapshots are never packaged.

Validation on 30 September 2026: native build, startup/import and automatic Results navigation smoke checks, real audit rendering, bundled PowerShell/module import, installer compilation and the packaged application's normal administrator audit passed. The live test confirmed resource grants, classic groups, directory membership and successful disconnect. Previously unavailable member names and usernames were resolved after separately granted User.ReadBasic.All consent. Synthetic checks cover identity lookup caching/failure/mismatch, endpoint allowlists, owner/member pagination separation, nested cycles, HTML escaping, inherited access paths, CSV formula protection and a PnP mutation-command regression guard. Local HTML browser visual preview was blocked by the browser's file-URL policy; report generation and content checks passed. Clean-machine install/uninstall and publisher signing are not yet verified.

File-review milestone, 2 October 2026: file traversal and report checks cover deep inheritance, unique file grants, denied ancestors, missing parents, out-of-library rejection, retained failures and unknown flags. The new live file-review validation requires administrator sign-in; previous live validation above covers the folder-only release.

Publication history check, 2 October 2026: GitHub reported the configured repository empty and private; the local workspace had no Git metadata. Thus there were no current Canopy commits containing the removed test defaults. This is a point-in-time check, not a guarantee about future commits, artifacts or other copies. Publication checks also reject private/generated paths already tracked by Git.

Local saved-site validation covers encrypted round trips, invalid targets, duplicate names, corruption preservation, recursive file scope and deletion. DPAPI protects at rest for the Windows account; it does not defend against another process running as that account. The app still requires Microsoft administrator sign-in for an audit.


Review, 2 October 2026: the collector has progressed faster than the product experience. The desktop now uses Lantern's single navigation rail and system/light/dark theme pattern, with separate Audit, Results, Coverage and Report pages. Named connections are an optional collapsed section; Run administrator audit stays visible at the default window size. Profile loading is explicit and never initiates authentication.

Before a client audit, complete the administrator file-level live validation and compare discovered items against independently known library totals and known unique/inherited permission examples. Full Control consent is broader than the collector's read operations; command guards help prevent regressions but do not reduce the token's capability or establish an absolute non-destructive guarantee. Sharing-link details and policy-dependent effective access remain outside the collected evidence. Preserve partial/unknown labels prominently in every report.

Next engineering priorities are per-item request batching with bounded retries/backoff, large-library measurement, bounded total membership expansion when importing snapshots, and transactional snapshot validation/rendering so a malformed import cannot replace a working view. Separate the large window class into presentation and collection services to keep Canopy and Lantern's UI patterns aligned. Clean-machine install/uninstall and signing remain outstanding. The completed dependency review is recorded in licenses/DEPENDENCY_REVIEW.txt; its scope is separate from the desktop project restore audit.

High-value follow-ups after validation: filters for unique permissions, external identities and unresolved evidence; a clear findings summary; and comparisons between two explicitly saved audit snapshots. Keep evidence available behind every finding. Private collaborator source is retained under ignored local work storage and is excluded from the distributable package.

The application executable, window/taskbar identity and installer use the canopy logo. The Windows icon includes 16 through 256 pixel sizes; shortcuts inherit it from the executable.

HTML resource hierarchy checks cover nested files, classic-to-Entra owner expansion, inherited source links, unknown permissions, missing parents and resource cycles. The tree is script-free and starts expanded; reopen any collapsed sections before printing.
